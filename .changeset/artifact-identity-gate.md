Refuse a rulings sidecar that sits off its rendered name. The fix dispatch composes the artifact matrix's read (names · presence · `misplaced` · `absent`) with the strict sidecar schema in ONE value, so the round-context cell and the pre-dispatch gate can never disagree: a sidecar that attributes to the reviewed round but is not its rendered name (`<line>-<op>-<cycle>.c<cycle>.rulings.json`) stops the round before the in-flight record and the child with `CDD_BLOCKED: artifact-identity` — every candidate listed, none selected, and a `repair:` section naming the rename the orchestrator owns. A rendered name that exists but cannot be read is `invalid(…, "unreadable")`, never `absent`. `--dry-run` prints the same refusal, so a preview cannot forecast a dispatch the real run refuses. The gate judges only the kind this round resolves (`rulings`), so a carrier spelled with an explicit `-a1` still dispatches.

The retired spellings are no longer read: the `spec` ledger row key (`RETIRED_SPEC_KEY` / `RETIRED_SPEC_LINE_KEYS`, `Ledger#rowFor`'s fallback and `#retiredSpecApplies`), the `spec-<op>-<round>.json` carrier (`#retiredCarrierName`), the cycle-less implement read rung (`#legacyCarrierName`) and the old row-key mappings (`#ownerRow` / `#lineWord`) are gone. A pre-P36 workspace now shows the missing document row plus `orphan:` observation lines — history is never rewritten, and no dispatch is refused because of it.

The four `--help` examples name `--plan <path>` / `--spec <path>` instead of interpolating a document root, and a structural door (`doc-path-door.test.ts`) fails any new template or `path.join` composition built on a doc root outside the three declared sites.
