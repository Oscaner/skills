fix: the branch line's dispatch surface unified — the fix channel becomes invokable, the line's identity and commit-ref form converge, and the re-review literal carries its full range:

- **Branch fix refs derived, never re-declared** — `cdd fix --type branch` was structurally un-invokable on the rebuilt engine: the work-scene assembly required `--base`/`--head` while the fix command's key set never declared them (every branch-fix dispatch hit `unknown option: --base` or `missing required --base`). The branch ref now lives in one place (`BranchRef` — a single identity class) and rides one carrier: `cdd review --type branch --base --head` declares it (the range's birth face), every other face derives it, and the fix reads the source review handoff's `commits`. The review `INPUT_RANGE` renders the short form (base7..head7) for the branch and wave faces alike (previously full-shas for branch, short for wave).
- **Line-identity convergence** — `--plan` renders on every branch literal (`cdd fix --type branch --findings …` / `cdd review --type branch --base … --head …` `next:`), so a follow-up fix/re-review lands in the same plan-slug workspace as its ledger instead of a bare-ref directory with an empty ledger (the `next round is branch-review` refusal). Handoff file names are line-keyed: the range token drops out of the names (`branch-review-dbbcd3d..ffc0c15-r1.json` → `branch-review-1.json` — the shas already ride the carrier's `commits`), reports become `branch-review-1-report.md` / `branch-fix-1-report.md` with the line's single `branch-test-evidence.json`, and the branch progress key is the stable `"branch"` per plan workspace, so rounds ACCUMULATE across a re-review loop (review-1 → fix-1 → review-2 → fix-2) instead of every head move resetting the round to 1.
- **8-char short shas engine-wide** — commit refs are the 8-char short form everywhere (`git rev-parse --short=8 HEAD` · `--base/--head` validation · the CLI sha channel · the carrier schema's commit row · a branch range's flags), 40-char full shas retired engine-wide (including the doc-revision content hash, `doc_hash`, sliced to 8). A legacy 40-char carrier still resolves — sliced at the one `BranchRef` decision, never re-sliced into a shorter token.
- **Re-review literal + doc-contract gate fixes** — a branch re-review `next:` literal (a fix round whose blockers remain) previously rendered `--base <sha>` without the runtime-required `--head` and exited 2 at the missing-refs gate; the fix-with-blockers route now carries the FULL reviewed range (base = the fix's base, head = the fix's head) and the literal renders both shas; a head-less route refuses the half-composed literal. The doc-contract gate accepts the titled task heading (`### Task N: <title>` — the tree-wide plan form, previously rejected by the registry's bare-heading pattern), the domain judge's code-span exclusion strips a nested backtick citation inside an outer quoted fragment (a spec's command-quoted prose was misjudged as `## Constraints`/`**Version**` values), and `pnpm run validate` gains a doc-contract step running the engine judge over every spec/plan doc — a new-form doc the gate would block at dispatch now fails CI.
