fix: dispatch / review-output / artifact contract convergence — the live two-channel dispatch table, a single-meaning output contract, round-keyed artifact naming, and no dead pointers:

- **Dispatch contract converges on the two live channels** — the fix face is de-referenced: `DISPATCH.fix` / `DispatchTable.fix` deleted, `#skillRef(fix)` returns null (mirroring spec/plan review), `REFS` drops its `mattpocock-skills:tdd` key, and the guard's `checkChannels` fix `pushRef` is removed so a fix-less dispatch table no longer raises. The `CHAINS` ordered-chain data plane and the `graph-node` ref kind (`RefKind` 4→3) are deleted — the wave-atomic model never reviews a single node. The fix fixed body gains two typed instructions: **verify-then-apply** (each finding checked against the codebase before changing; unsound findings kept as notes, never blindly applied) and **conditional TDD** (a behavior-changing fix without a test opens red→green first).
- **Handoff carrier carries only schema-declared writable fields** — the engine-seated identity (`phase` · `tasks`) is no longer written inline; the canonical file name (`tasks-{wave}-*.json` / the branch range / the doc family) is the sole identity. The inline identity was never declared in the writable subset yet was materialized by the engine, seeding a mimicking precedence that tripped the reserved-field gate (a fix draft copied `phase` and was rejected — correctly, but avoidably).
- **Closed-wave routing** — `cdd review` / `cdd fix` route a closed wave to the next wave (`next: implement wave …`) until the terminal wave; `next: done` renders only when the run is actually exhausted. The closure router judges the ledger's cross-invocation closed set (`closedWaves()`), not the per-invocation in-memory cursor; the CLI dispatch loop peeks the next frame before advancing, so a mismatch never spends the next phase's round.
- **Review output contract unified** — the task/branch return block drops the `blocker:` prose column (BLOCKED reasons route exclusively to stderr `CDD_BLOCKED:` + `failure_category`; the return block is the 4-line `status`/`commits`/`artifacts`/`counters` contract); status↔severity equivalence is pinned in engine tests (`CHANGES_REQUESTED` ⟺ ≥1 `severity=blocker`); claim scans are structural (head-clause `Pending`/`[Pending]` + non-parenthetical), multi-target ranges declare only at the declaration slot with an expanded-phase diagnostic payload; branch-review emits the return block through the single return-block point, the doc-audit gate runs on the branch path (missing-root real mode → `CDD_BLOCKED` exit 1, dry-run → WARN), `--root` is whitelisted on implement/review/fix, and branch-fix receipts are engine-materialized facts (a committed fix with no code-plane error self-heals to APPROVED; the injected schema writes only the writable subset). The `next:` suggestion line (derived by pure `next-step.ts`) now lands on all three output faces; on fix, the next hop is judged by the input findings' `convergence.blockerCount` (blocker>0 → re-review on the moved ref, warn/nit-only → `next: none` closure, soft-cap exhausted → `next: BLOCKED: review-cycle-cap`) — a default next hop the mid-flight world state may override.
- **Round-context zero dead pointers + prescribed artifact names** — the dispatch round context drops the dead `INPUT_RULES` pointer (implement children read the plan's `## Constraints` section directly through `INPUT_PLAN` — no materialized `plan-constraints.md`, no dead file path in the prompt). Artifact names become a single prescribed scheme: the round context injects canonical `OUTPUT_BRIEF` / `OUTPUT_REPORT` / `OUTPUT_EVIDENCE` write paths (family-keyed `{family}-{key}-{artifact}` — `tasks-1,2-implement-report.md` · `spec-review-1-report.md` · `branch-test-evidence.json`), review/fix rounds are round-keyed so a re-review never overwrites its predecessor's files, and a child-declared free-named path is corrected to its canonical name with the deviation surfaced on the carrier's notes. The `cdd review --type wave` `next:` literal renders its runtime-required `--plan <path>`, and the plan-graph board's wave labels start at W1 (wave index + 1, no zero-padding), matching the plan's execution-order labels verbatim.
