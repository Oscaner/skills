refactor: doc-architecture-v2 P1 + P2 — doc types become the single home of the shape / words / bodyView / token planes, the schema + lexicon configs become derived products, and the per-type dispatch converges on the doc-type registry. Internal restructuring only, zero consumer-facing regression:

- **DocType five-domain framework** — a new `abstract DocType` (shape / words / bodyView domains, the `instructions`/`refKind` seams, route metadata + detect/validate/parse/lifecycle/parentChain) plus a `DocTypeRegistry` singleton with fixed [overall, plan, spec] iteration; overall/plan/phase-spec subclasses own their per-type validation/parsing, and `DocumentsValidator` delegates through `resolve(kind)` — external validation behavior unchanged.
- **Derived product plane** — `SchemaFactory` renders `config/schema/{phase-spec,plan,overall}.json` from the shape domain (`JSON.stringify(shape, null, 2) + "\n"`, deterministic byte-faithful projection) and `config/contract-lexicon.json` renders from the shared `DocWords` singleton; content edits land in `doctype.shape` / `doctype.words`, never in the products. `bodyView` absorbs `reviews.{spec,plan}` + the `DOCS_FORMATS` discriminator (`template-contract.json` keeps shell/tokens/clauses + `reviews.{task,branch}`). Doc-kind detection, CLI review/fix `--type`, `resolveTargetDoc`, and the next-step suggestion rows all route through the registry (`docKindOf` and the implicit spec fallback retired — zero detect hits fail fast). `deriveDocTokens` reads the shape domain directly instead of re-reading the derived schema products.
- **DocBody abstract contract** — the concrete per-type body is the single source of the schema shape, the parse slabber, and the token-plane leaf: `DocBody` (kind identity + authoring-way description) with two mandatory projections — `projectSchemaShape()` re-derives the `DocType.shape` domain, `projectSlicePatterns()` re-derives the parse slice regexes — plus the shared `## Constraints` heading atom. The phase-spec body is the three-truth skeleton (`## Design` with the unique `### Acceptance criteria` subsection · `## Constraints` as the delta-only inheritance point) plus the conditional sections (incremental warning / deviations / notes for downstream / review record). The plan body is the task-records data form (`### Task N:` + objective / files / interface / steps[]{action,checkable} / acceptance[]), the brief renderer materializing the task-handoff brief from (zero prose `- **Do**:` carving) and `renderBrief(task)` asserting the brief's shape by fixture.
- **Dual-read contract + zero regression** — legacy six-segment / Form B and new-form docs stay double-readable (both validate + parse paths accept both shapes); task numbers / brief / constraint extraction flow through the single projected slice source; `deriveDocTokens` keeps its pure-function signature with production values byte-pinned; `cdd schema get <type>` behavior unchanged; the schema products remain SchemaFactory-derived at byte fidelity.
