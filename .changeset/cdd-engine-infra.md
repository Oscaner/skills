refactor: engine infrastructure convergence — zero-build architecture, the host-marker domain, and the workspace data-plane consolidation:

- **Zero-build architecture** — the publish face is compiled JS only: `bin`/`main`/`exports["."]` point at `dist/bin.js`, produced by a single `tsc -p tsconfig.build.json` pass (`module: nodenext` + `rewriteRelativeImportExtensions`, shebang preserved); the `config/` tree is copied to `dist/config/` so published-first resource resolution is unchanged, and the package ships `dist/` + `config/` + `templates/` — `src/` sources are never published (Node permanently forbids type-stripping under `node_modules`). The dev/CI face is zero-build: `node packages/cdd-engine/src/bin.ts <subcommand>` runs the source directly (Node ≥ 22.18 native type stripping); the vitest black-box surface, the smoke-cdd pin, and the documented dev chain all invoke that entry. Dead build machinery deleted (unbuild, jiti, the stub dev script, the root build config, the global-setup self-stub) and `engines` raised to `>=22.18.0`. Non-breaking: the `cdd` bin name is unchanged and the package has zero API consumers.
- **Host-marker domain + three-way guard** — the engine's harness contract gains per-harness `detect` data: `claude` (`CLAUDE_CODE_SESSION_ID` + `claude-code` prefix), `cursor` (`CURSOR_TRACE_ID`), `pi` (`AI_AGENT=pi`); the engine-config env whitelist declares the same keys plus `PATH`. A three-way consistency guard (`checkMarkers`) pins the contract against the `harness.ts detect()` predicates and the env whitelist — drift on any face is a validate finding.
- **Workspace data-plane consolidation** — one `WorkspaceRoot`/`Workspace` domain owns every on-disk workspace concern: the workspace derivation, the root-level `.kairos/.gitignore` self-guard (`*\n`, a fresh repo's first cdd run writes its own guard), `Workspace#for(doc)` slug derivation, the per-workspace atomic JSON read/write pair, and the child-path single facts (`progressPath` / `briefPath` / `lifecyclePath`). The process-lifecycle registry lands per workspace slug (`<workspaceRoot>/<slug>/lifecycle.json` instead of a repo-level single file), and the startup sweep (`reapStale`) enumerates every slug's `lifecycle.json`. `ProgressLedger` and `Handoff` take the canonical `Workspace` at construction; the scattered `mkdirSync` sites converge on `Workspace#ensure`.
