fix: engine robustness family — crash-only recovery with a unified termination model, op-keyed dispatch budgets, and the clean-tree workspace exclusion:

- **Crash recovery (crash-only snapshots + records, stash plane deleted)** — `HARNESS_ABORT` joins `engine-config.json#failureCategories` (the deterministic-recovery class for harness/model 403-style child aborts, per-category independent convergence quota). A child that exits non-zero without writing its handoff now: ① preserves the child stdout/stderr tails (~40 lines), ② commits a crash-only snapshot (`git add -A && git commit --no-verify`, no-op on a clean tree), ③ writes a crash record to `Workspace.crashPath(lane, round)` (`{exitCode, stderrTail[], stdoutTail[], snapshotSha, attemptedHandoff, next}`), and ④ emits the BLOCKED capsule with the same-command resume `next:`. A repeated abort on the resumed round re-fires the teardown (stale engine-terminal carriers rotate before re-dispatch) instead of being suppressed. `stashPush/stashApply/stashMessage`, the `recovery` handoff carrier, the settleResidue stash template step, and the residue stash vocabulary are deleted — recovery normalizes onto the commit ledger and the crash record (zero program branch memory).
- **Unified termination model** — every pre-exit-gate termination now runs the SAME crash teardown, whatever the death: the engine side (over-budget / timeout-stall) and the child side (non-zero exit / signal) share one implementation path, with a single `crashCauseFor` classifying the death into the crash record's `cause` vocabulary (`child-exit` · `child-signal` · `engine-over-budget` · `engine-timeout` · `unknown`); an engine-terminated round routes to the TIMEOUT category (carrier `status: TIMEOUT`) instead of being misclassified as a child death. The resume `next:` suggestion rides the BLOCKED and TIMEOUT capsules alike, resume-pending is derived from crash-record PRESENCE, startup `reapStale` enumerates each slug's `crash-*.json` records and reaps the stale ones, and a resolved round clears its own record (the dual-artifact invariant: a round terminates at exactly one artifact — handoff or crash record). The docs/branch lanes mirror the task lane's repeat-abort behavior (a second consecutive abort re-fires the teardown), and their no-handoff lanes thread `timedOut`/`cause` through `crashCauseFor` with the same two-way shape.
- **Crash-recovery soft cap** — one crash teardown increments a per-task recovery count (`progress.json` `tasks[N].recovery_count`); reaching `CRASH_RECOVERY_CAP_ROUNDS` (3) routes the resume suggestion to user adjudication (`BLOCKED: crash-recovery-cap`). The count is a per-row fact measuring the CONSECUTIVE streak (a normal-face round resets it; 403/OOM/over-budget incidents never burn the failure-category caps).
- **Op-keyed dispatch budgets** — `engine-config.json#contextContract.timeouts.defaults` moves from `{task, review}` to `{implement: 21600000, review: 10800000, fix: 21600000}` (fix shares the implement amount; the `task` key deleted). Every dispatch island resolves its termination budget by its ACTUAL op — a `cdd review --type task` round previously read the implement budget through a hardcoded key, docs fix read the review budget, branch-fix read the review budget; branch-review keeps `review` (its op IS review). `DispatchOp` (`"implement" | "review" | "fix"`) + `DEFAULT_TIMEOUTS: Record<DispatchOp, number | undefined>` make a non-op budget key fail at compile time. Seven wiring-layer tests pin budgetMs at the invokeCli seam (the regression gate that was missing while the wiring bugs were live).
- **Clean-tree workspace exclusion** — the clean-tree dispatch gate keeps pure git semantics: uncommitted user work still refuses it (dirty → BLOCKED), while the engine's own run state never counts as user work. The engine workspace self-publishes a keep-out `.gitignore` (content `*`) at the `.kairos/` namespace root at ensure time, before the gate reads the tree — consumer repos without a `.kairos` gitignore no longer self-BLOCK once a dispatch lands its own artifacts, and those artifacts stay out of commits and branch diffs with zero consumer setup. Stale `naming.ts` references (the residue guard carve-out + doctrine anchors, the mirror test comment, the tinyglobby dependency-row anchor) now point at the migrated surface (`src/infra/workspace.ts` + `src/artifacts/handoff.ts`).
