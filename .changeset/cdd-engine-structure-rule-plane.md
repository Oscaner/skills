feat: doc-architecture-v2 P3.1 — the document tree's structural grammar becomes one rule interpreter: a unilateral rank-gated edge model, registered outline ranks, the body rule sets enforced at the dispatch doc-contract gate, and the handwritten four-table walkers zeroed:

- **Unilateral edge model (plan)** — a task block declares exactly one directed edge: `- **DependsOn**: <n, n, …>`; `none`/empty is the explicit no-dependency declaration (both resolve to an empty edge set). A task block missing its `- **DependsOn**:` line is a validate BLOCK (the missing-edge failure class); each cited id must be lower than the declaring task's own number (a forward-rank edge is the anti-dependency BLOCK); malformed comma values (`abc`, `1;2`) are rejected, never silently swallowed; ids beyond the plan's task count are the rank-gate exemption.
- **Wave-derived dispatch (task graph)** — `batches()` walks the declared edges into ready waves: each wave is a layer whose every dependency is satisfied by earlier waves, tasks ascending within the wave; a no-dependency task list is the single root wave. `effectiveGroups` consumes the waves as the dispatch groups — every `### Task N:` belongs to exactly one dispatch group, and that group list is the engine's single group derivation. A broken edge model (missing-id / malformed value / self-loop / forward-rank contradiction / cycle) BLOCKs the plan and never yields a silent order.
- **Registered outline ranks (spec + overall)** — the spec design body's outline ranks are machine-registered: `### N.` group headings owning `#### N.M` item leaves, under the single `### Acceptance criteria` anchor; unregistered `###` headings, rank-doubled headings, hollow or unowned item leaves, and standalone bold pseudo-headings are structure BLOCKs. The overall charter's facet `###` and decision-leaf `####` ranks ride the same registration plane.
- **Reference-lint observation pass (plan)** — each task block's Objective/Acceptance prose is scanned for cited lower-numbered tasks the block's own `- **DependsOn**:` does not declare: one WARN per suspected missing edge, aggregated to at most one per block. A loose observation, never a validate gate — forward/self references, out-of-range ids, code-span numbers, `- **Steps**:` entries and non-acceptance bullet fields are constructively excluded; author intent is authoritative.
- **Body rule sets live at the gate** — the three doc bodies declare their structural demands as rule data (`structureRules()`): the plan's task continuity / data-shaped record faces / constraints-source / legacy-residue rules, the spec's three-truth skeleton rules, and the overall's four-table kernel / change-history / dependency-graph rules. The dispatch doc-contract gate interprets the ENTRY doc's resolved rule set and — the chain-compounding face — the parent overall's rule set on the chained doc a plan/spec entry reaches, judging both by severity (BLOCK blocks, WARN warns). The overall's handwritten structural walkers (kernel header / change-history version-order-date numerics / dependency-graph token membership) are removed in favor of the one interpreter; the overall validate keeps only the irreducible contextual residue (row-shape guard, merged version-lineage, file-existence kernel face, the backfill-claim / doc-existence / registration / anchor / issue-row faces).
- **Section-scoped records plane** — the interpreter gains an optional `within` anchor for `records` rules (a run opened by a field/section marker, closed by the structural-boundary family), so the plan `checkable` demand scopes to `- **Steps**:` field lines exactly — a numbered line in Constraints prose or a code fence never demands a checkable.
- **Behavioral surface** — a plan/spec/overall entry whose structural face violates its body rule set now BLOCKs the doc-contract gate (previously enforced only via the per-type validate walkers, with the overall's structural verdict carried twice).
