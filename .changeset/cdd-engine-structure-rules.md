feat: doc-architecture-v2 P3.1 — the document-tree structural grammar's edge model is unilateral and rank-gated, the spec/overall outline ranks are registered, and the plan gains a reference-lint observation pass; dispatch waves derive directly from the task records' declared edges.

- **Unilateral edge model (plan)** — a task block declares exactly one directed edge: `- **DependsOn**: <n, n, …>`; `none`/empty is the explicit no-dependency declaration (both resolve to an empty edge set). A task block missing its `- **DependsOn**:` line is a validate BLOCK (the missing-edge failure class). Each cited id must be lower than the declaring task's own number — a forward-rank edge is the anti-dependency BLOCK; malformed comma values (`abc`, `1;2`) stay rejected, never silently swallowed; ids beyond the plan's task count are the rank-gate exemption.
- **Wave-derived dispatch (task graph)** — `batches()` walks the declared edges into ready waves: each wave is a layer whose every dependency is satisfied by earlier waves, tasks ascending within the wave; a no-dependency task list is the single root wave. `effectiveGroups` consumes the waves as the dispatch groups — every `### Task N:` belongs to exactly one dispatch group, and the group list is the engine's single group derivation. A broken edge model (missing-id / malformed value / self-loop / forward-rank contradiction / cycle) BLOCKs the plan and never yields a silent order.
- **Registered outline ranks (spec + overall)** — the spec design body's outline ranks are machine-registered: `### N.` group headings owning `#### N.M` item leaves, under the single `### Acceptance criteria` anchor. Unregistered `###` headings, rank-doubled headings, hollow or unowned item leaves, and standalone bold pseudo-headings are structure BLOCKs. The overall charter's facet `###` and decision-leaf `####` ranks ride the same registration plane.
- **Reference-lint observation pass (plan)** — each task block's Objective/Acceptance prose is scanned for cited lower-numbered tasks the block's own `- **DependsOn**:` does not declare: a match is one WARN (a suspected missing edge), aggregated to at most one per block. It is a loose observation, never a validate gate — forward/self references, out-of-range ids, code-span numbers, `- **Steps**:` entries and non-acceptance bullet fields are constructively excluded, and the author's intent is authoritative.
