refactor: P1 doc-architecture-v2 — doc types become the single home of the shape/words/bodyView domains, the schema + lexicon configs become derived products, and per-type dispatch converges on the doc-type registry (S1-S8). Internal restructuring only: the derived products are byte-equivalent to the pre-P1 files (parse-deep-equal, whitespace-only normalization — accepted deviation: the products' on-disk baseline is REGISTERED as the canonical JSON.stringify projection, not the pre-derivation authored bytes; diff pins lock this derived baseline), production `DOC_TOKENS` / vocab values are unchanged, and no consumer-facing behavior moves.

- **DocType five-domain framework (T1/T2, S2/S3)** — new `abstract DocType` (shape / words / bodyView domains, the P5 seams `instructions`/`refKind`, route metadata + detect/validate/parse/lifecycle/parentChain) plus a `DocTypeRegistry` singleton with fixed [overall, plan, spec] iteration; overall/plan/phase-spec subclasses own their per-type validation/parsing, and `DocumentsValidator` delegates through `resolve(kind)` — external validation behavior unchanged.
- **Derived product plane (T3/T4)** — `SchemaFactory` renders `config/schema/{phase-spec,plan,overall}.json` from the shape domain via `JSON.stringify(shape, null, 2) + "\n"` (deterministic byte-faithful projection); `config/contract-lexicon.json` renders from the shared `DocWords` singleton; `infra/word-table.ts` and its consumers are unchanged. The on-disk schema/lexicon products are diff-pinned against this canonical derived baseline — content edits land in `doctype.shape` / `doctype.words`, never in the products.
- **bodyView split (T5/S7)** — `reviews.{spec,plan}` + the `DOCS_FORMATS` discriminator migrate into `DocType.bodyView`; `template-contract.json` keeps shell/tokens/clauses + `reviews.{task,branch}`; TemplateLoader resolves per-type config through the registry with equivalent render output.
- **Registry dispatch convergence (T6/S1/S4/S5/S6)** — doc-kind detection, CLI review/fix `--type`, `resolveTargetDoc`, and the next-step suggestion rows all route through the registry (`byReviewType` / `route.argKey` / `route.targetFlag`); `docKindOf` and the implicit spec fallback are retired (zero detect hits now fail fast).
- **Tokens derive from the shape domain (T7/S8)** — `deriveDocTokens` reads the three shape faces (`doctypes/shapes/*`) instead of re-reading the derived `config/schema` products via `loadDocSchema`; production `DOC_TOKENS` values byte-unchanged; stale `documents/schema/` + `ex lib/` residues cleaned.
