feat: unified termination model — every pre-exit-gate termination runs one crash teardown, crash records carry a `cause`, stale records reap by artifact enumeration, and crash recovery has a per-task soft cap.

- **Teardown predicate widened** — the crash teardown trigger is now ANY dispatch that terminates before the exit gate with its handoff unwritten (the dual-artifact model: a round terminates at exactly one artifact — the handoff on the normal face, the crash record on the abnormal face). Engine termination (over-budget / timeout-stall) and child death (non-zero exit / signal) share the SAME implementation path — a single `crashCauseFor` classifies the death into the crash record's new `cause` vocabulary (`child-exit` / `child-signal` / `engine-over-budget` / `engine-timeout` / `unknown`), postmortem-only, zero behavior fork.
- **Crash record tri-party unified** — teardown writes / resume reads / reapStale enumerates: the resume `next:` suggestion now also rides the TIMEOUT capsule (the router's crash-record recovery row covers BLOCKED and TIMEOUT), resume-pending in `deriveTaskState` is derived from crash-record PRESENCE (the handoff carrier's dead face is retired with the legacy recovery-carrier persistence), and startup `reapStale` enumerates each slug's `crash-*.json` records and deletes the stale ones (a record whose round has since terminated at the normal face). Resolved rounds clear their own record on dispatch completion (the dual-artifact invariant).
- **Crash-recovery soft cap** — one crash teardown incrementally persists a per-task recovery count (`progress.json` `tasks[N].recovery_count`); reaching `CRASH_RECOVERY_CAP_ROUNDS` (3) routes the resume suggestion to user adjudication (`BLOCKED: crash-recovery-cap — user adjudicates`). The count is a per-row fact, never a FailureResolver category counter — 403 / OOM / over-budget external incidents do not burn the category caps.
- **Category identity / mechanism decoupled** — `failureCategories` stays the identity face (counter / terminal / channel-audit per category, unchanged); the post-termination mechanism is single-path (snapshot + record + resume), with the legacy independent recovery persistence gone.
