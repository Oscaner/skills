**One read/write path for the working tree — the in-flight record, the strict lock, and the plan-ledger gate (P21).** A dispatch now records its intent before it spawns: an `InFlight` record (pid, command, start time, wave, slug) written under the exclusive lock the engine keeps for the working tree, updated by the sampling loop and released on every graceful exit. A second dispatch in the same tree is refused — any slug, not only its own — and the refusal names the holder (pid, command, started time, elapsed time, wave, slug). The judgment is the record's existence plus its holder pid's liveness; whether the lock is still held never decides anything, because a clean exit removes its own lock. A record whose holder is gone is refused too, and the only takeover path is the explicit `--steal-stale` flag (`implement` / `review` / `fix`, never `--dry-run`, which keeps its zero-write preview and exits 1 while the tree is held). An unreadable record is a three-state fact, not a fail-open: unreadable and locked stays held, unreadable and unlocked stays held, and the sole exit is `--steal-stale` — never a silent clean. `board` and the preview report the takeover as a hint and write nothing. Process facts move behind one OS read face: `ps-list` answers liveness, the PPID chain and the start-time tolerance that guards pid reuse (`|startTime − startedAt| <= 60s`; an unreadable start time is treated as a live holder), while the process-GROUP cumulative CPU reading stays `ps -g` as the declared exception to "prefer a mature package" — `pidusage` is never adopted, and a PPID descent would miscount a leader that exits and a `setsid` grandchild. Three runtime dependencies join (`proper-lockfile`, `write-file-atomic`, `ps-list`), and the standalone `liveness.json` diagnostic product is gone — one writer, three readers, one record.

The pre-flight runs in a fixed gate order — `tree-clean → in-flight → graph → plan-ledger → wave → doc-contract` — and renders that order with the checked list. The new `plan-ledger` gate evaluates the two ledger-scope rules (`closed-wave-fits-depends-on-layers` · `planned-tasks-vs-recorded-tasks`) on plan, wave and branch dispatches, and both rules now derive from the contract's rule-declaration plane instead of fifteen hard-coded constructions. "The plan leads the ledger" is an informational row (`plan-ledger: info (plan leads ledger by N tasks)`), never a refusal: a wave's planned tasks legitimately run ahead of the recorded ones. Appending mid-plan is a supported path and it is decided on fact, not on a new declaration field — every closing wave row stamps the plan's task set at that moment, so a mixed batch's unstarted member is an append when it is absent from the snapshot (it dispatches as a new wave) and a stale entry when it is present (it stays `mixed-batch`). A wave row without a snapshot reads as unknown and stays conservative. The plan document's own shape moves with it: task blocks are `### Task N:` sections whose fields are `####` headings, and `cdd schema get plan --output skeleton` emits only that form — while the former `- **Field**:` bullet shape stays readable as input, so an existing plan parses unchanged.

Round counters read as CYCLE numbers, not ordinals: `rounds.fix = [2,3]` means the fixes of review 2 and 3, and `board` renders it that way (`review×1,2,3 · fix×2,3`). Crash artefacts now derive their name and their attempted-handoff pointer from the round's single identity, so a crash record names its real wave, the stale artifact name is gone, and `CrashRecord` gains the two post-hoc facts `dispatchBase` (HEAD before the dispatch) and `commitsSince` (the commits landed after it) — diagnostics only, outside every reviewed identity and every gate.

The kairos skills carry the consumer face of the same contract: `cdd-plan` declares how appended work enters (real `DependsOn` edges onto closed tasks, a fresh wave, no rewrite of a closed task's content, `Acceptance` as usual), and `cdd-dev` states that a ledger behind the plan is a hint rather than an error and quotes the three canonical recovery sentences — look at the working tree first · commit the changes that work · discard the ones that are broken. The same three sentences are the engine's word face, and a regression gate keeps `pgrep`, `git stash` and `checkout --` out of every shipped skill.
