**A charter is judged by charter criteria.** `cdd review --type overall` no longer borrows the phase-spec narrative criteria: the charter has its own criteria body with its own five lenses — `scope` · `inventory` · `dependency` · `acceptance` · `boundary` — and it judges six things, and only those: each phase's Scope names a program increment rather than implementation detail; the Phase inventory, the dependency graph and the documented execution order agree (every edge marked hard or soft, every order one the edges allow); each acceptance cell is decidable when its phase closes; the Non-goals actually fence the program; the change record is a decision record rather than a work log; and the inventory agrees with the tree (a closed phase is marked Done, and work no registered phase carries never appears as a delivered increment). A charter review carries none of the implementation-face evidence duty: the reviewer is not asked to run the repository's typecheck or test commands, and not to pin every claim to a `path:line`. Lending the charter the phase-spec criteria is what pulled implementation detail into charters — the charter owns the program's shape, never a phase's code. The shared severity calibration still rides every criteria body unchanged (the four blocker questions, the silence-is-not-permission sentence with its artifact / audience slots, the set-aside ledger and the closing acknowledgement).

Criteria-body selection is now explicit (`ReviewVariants.of`): `wave` · `branch` · `plan` · `overall` each select the criteria body of their own name, and the two spec-shaped document targets (`phase-spec` · `single-spec`) share the ONE narrative body under the `spec` criteria key — a second prose copy does not exist. The criteria line of a review prompt still speaks the target-type word the `--type` flag declares, so a `phase-spec` or `single-spec` review keeps naming its own document shape while reading the shared body. The template contract's `$version` moves to 20 (the `overall` row's fixed prefix changed).

The package README (both languages) gains a review-criteria table: one row per target type, naming the criteria body each one selects and the charter's charter-only rule.
