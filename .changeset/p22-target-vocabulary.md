**One target vocabulary — from the CLI to the pipeline (P22 D73).** The engine's target types are now the six words the documents themselves declare: `phase-spec`, `overall`, `plan`, `single-spec` (the document shapes) and `wave`, `branch` (the node shapes). `--type spec` is retired and the `spec ⇄ phase-spec` translation class is gone, so a dispatch names its target once and every downstream face reads that same word: the faces table (`targetFaces`), the pipeline table (`PIPELINE_NEXT`, now keyed by `TargetType`), the ledger line keys, the handoff carrier names, the round report/log names, the crash records and the rendered `next:` literals.

Consumer-visible effects. `cdd review` / `cdd fix` accept `--type phase-spec` (the previous `--type spec` spelling is rejected by the enum); `--type overall` and `--type single-spec` are dispatchable targets of their own, each with its own round line (`overall-review-N`, `single-spec-review-N`) instead of folding the charter's rounds into the phase-spec line — the board's `overall` row reads the `overall` line and its `spec` row reads the line the document itself declares (`phase-spec` for a phase spec, `single-spec` for a standalone spec), including that line's own pipeline station (a closed `single-spec` renders `done`, never the phase-spec line's `cdd-plan` handoff). The `--spec` flag is retained unchanged; only its help text now reads "the document under review — a phase-spec, an overall charter or a single-spec". The doc-contract gate judges all four document shapes by the document's declared `doc-type:` key rather than by the command's `--type`.

Renamed engine artefacts (the byte face of a run in progress). A phase-spec round's carrier is `phase-spec-review-{round}.json` / `phase-spec-fix-{round}.json` (previously `spec-*`), and the overall / single-spec lines carry `overall-*` / `single-spec-*` families; round reports, logs and crash records follow the same `{type}-…` stem. Rounds already on disk under the retired spelling are never rewritten; they are still READ. A one-release read alias resolves a `spec`-keyed ledger row and a `spec-review-{N}.json` / `spec-fix-{N}.json` carrier as the line the workspace's identity document DECLARES — a phase that was mid-flight across the rename keeps its recorded reviews and fixes, and so does a charter (whose pre-rename rounds sat under the retired spelling because `spec` was the only document word the enum carried). Before this release a legacy row rendered no round counts and its `next:` re-opened the line at `review`; after, the line renders its counts again and a closed line stays closed, handing off to the next pipeline face (or, for a standalone single-spec, to the terminal `done`). The alias is scoped to one ledger file, and that scope is what makes it unambiguous: a ledger lives at `.kairos/cdd/<slug>/progress.json` keyed by the reviewed document's own declared `slug:`, so a charter's rounds sit in the program-slug workspace and a phase's in the phase workspace — within one file a retired `spec` key can only be that workspace document's own line, so the declaration names which line word reads it. New rounds book on the same row (a stored row key is never rewritten) while their carriers are written under the new spelling — the alias is read-only, and it retires with the release after this one. The alias also reports the name it resolved: a hop that points the next round at a migrated carrier (the rendered `--reviews`, `INPUT_REVIEWS`, the fix criterion's input set) names the file that exists, so a fix round mid-flight across the rename reads the review it must dispose of instead of an empty canonical path. `PipelineKey` is now derived (`Exclude<TargetType, "single-spec">`), and the `overall` / `single-spec` pipeline rows are the program-level terminals (`{ kind: "done" }`).

The kairos skills carry the consumer face of the same rename: `cdd-spec-writer`, which authors all three document shapes, dispatches its review round with the session target's own word — `review --type <single-spec|phase-spec|overall> --spec <path>`.
