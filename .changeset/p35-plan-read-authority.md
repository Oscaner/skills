The plan is read once per command, and that read is the authority for every face.

- `PlanSource` is constructed once in the command preamble and threaded to the work scene, the board chain, the pre-flight and the ledger — nine former read points (the scene, the wave board, the usage check, the pre-flight graph gate, the plan-ledger facts, the plan-ledger input, the lifecycle snapshot, the brief and the ledger's brief revision) now share one `PlanRead` value, and the three policies they used to apply (render `null`, throw, swallow) collapse into four explicit states: undeclared, unreadable, ready and the orphan mark.
- `BriefRenderer`'s three faces take `(text, doc, tasks)`: the renderer owns no parser, `WorkScene.plan` replaces `planText`, `PreFlightContext.plan` replaces `planText`, and the lifecycle's plan path becomes a read value instead of a string it re-reads.
- A non-ready plan degrades to the empty run state instead of throwing; a plan the argv names but cannot read still stops at the usage face (`cannot read file: <path>`, exit 2); a plan the GRAMMAR refuses no longer aborts the round when the dispatch measures its verification cell — the document reads as "declares no empty `Files` row", the shape an absent or unreadable plan already had.
- Every plan-carrying dispatch face (`wave` / `plan` / `branch`) refuses a plan the read cannot turn into a document: the existing `doc-contract` gate and reason token are reused (no new token), the message names the plan path and, for a grammar break, the offending field, and the refusal runs before the graph gate and before the wave brief — so a broken plan never reaches a renderer. `--dry-run` refuses with it.
- A plan whose `slug:` names no `<slug>-design.md` is refused the same way on those three faces: a plan is written for one phase, so an orphan is an identity break rather than a look-ahead gap. The reverse lookup probes existence only — a `<slug>-design.md` that is present but unreadable is not an orphan, and the board renders that spec row as the undecided `(none)` instead of fabricating `! no-spec`.
- `slug` remains the whole identity: a phase whose plan sits on a file name other than `<slug>.md` reads as "no plan yet" (`wave     (none)`, exit 0) with no error and no fallback to an index guess.
- The pipeline frontier takes the command's plan read instead of a separately injected graph, so its wave face and its `next:` cells read one document through one parse, and the lifecycle no longer carries a second plan-graph field. Doc faces take their plan path from the read itself: a plan that reads out is entered even when the index does not register it, a plan whose bytes do not read keeps the phase-spec hand-off (`route to kairos:cdd-plan skill`), and a plan whose grammar breaks routes to the plan face's exit phrase (`route to kairos:cdd-dev skill`) rather than a literal that fills in the path.
- The branch line's reviewed plan revision is read through the same seam as every other plan read (`PlanSource#readPath`) instead of a raw byte read of the path the scene handed over: a round that closes over a plan the read cannot turn into a document records no identity at all (present facts only, the same failure face as the wave brief revision), so the next board cannot read that line as drifted off a revision it never bound.
- The board holds no plan read of its own: `BoardView.planGraph` is gone, `Cli#runBoard` builds the ordered per-phase table (`index.phaseSpecsOf` row order) once and hands it to `BoardView.render` / `#programBoard`, and the node board, the wave segment, `pipelineFacts` and `BoardNext.of` take a single value — so the board can no longer report one document and route on another.
- The plan row is decided status-first: `unreadable` and the `spec-absent` orphan render `<repo-relative path> · <mark>`, a healthy indexed plan keeps today's `name version · status` cell, and a readable plan the index does not name renders the bare path. A broken identity keeps the existing `(BLOCKED)` marker and exit 2.
- `cdd board --plan` on a present but unreadable plan now refuses with `cdd board: cannot read --plan <path>` (exit 2, no board) instead of the not-found face; the classification order is existence → bytes → index membership → grammar, and a board that also carries `--spec` never opens the `--plan` bytes.
- A phase with no plan still renders `(none)` (program cell `""`), a healthy plan with no task block renders `(empty plan)`, a read failure renders `! unparseable` / `! unreadable`, and a plan whose `slug:` names no `<slug>-design.md` folds every derived cell to `! no-spec` and leaves exit 0.
- Every bad plan, orphan and slug-less plan writes one `CDD_WARN:` line to stderr (stdout unchanged); a plan that cannot be read or names no phase also derives no wave route (`next:    (none)`, no `reason:` row).
- One read per command means every wave-bearing face agrees: the board's `W1 {…}` rows, the graph the pre-flight judges and the frontier's wave keys are the same list, and a plan that changes on disk after the read never makes one face report a different document.
