feat(engine) + refactor(kairos): P6 engine doc-tooling — the fourth doc type (`single-spec`) lands, the doc-key vocabulary unifies on the `-spec` suffix, the kairos suite migrates to vitest, and the outdated docs are pruned (pending — no publish):

- **`single-spec` doc type + lightweight scaffold** (new capability) — the engine gains its fourth doc type: `DocKey`/`DocType` widen to `single-spec | phase-spec | overall-spec | plan`, a standalone `SINGLE_SPEC_ELEMENTS` registry row joins the declaration plane, and the Projector / Schema / Skeleton projections widen with it. `cdd schema get single-spec --output skeleton <target>` writes the lightweight scaffold straight into the target document (header five-tuple + `:::fill` body slots + Change history table; no `### N.` two-level outline, no mandatory Parent program); `--output json` prints the schema declaration without a target (target conditionally required, reusing the P5 mechanism). The filled skeleton passes doc-contract judgement by construction; all registered anchors are covered by the slot-consumption assertion.
- **doc-key vocabulary unification** (`overall` → `overall-spec`) — the doc-key vocabulary value domain renames as a deliberate byte sync: `DocKey`/`DocType` = `single-spec | phase-spec | overall-spec | plan`, the declare registration keys (`OVERALL_SPEC_ELEMENTS` + registry rows), the judge `DOC_KEYS`, the skeleton dispatch (`case "overall-spec"` → `#renderOverallSpec`), the `SCHEMA_TYPE_KEYS` rows, and the judge derivation (`-overall.md` → `overall-spec`) follow. Physical file names `*-overall.md` are untouched, `plan`/`phase-spec` keep their names, and the `plan-graph` display type + the `phaseSpec` input alias are retained — the consumer-surface skill variant literals (`single-spec`/`overall-spec`) sync, and the engine test pins + snapshots (`project.*.overall.snap` → `*.overall-spec.snap`) deliberate re-anchor. Zero behavior change — the doc-contract judgement semantics, exit-code table, `CDD_BLOCKED` channel, and `next:` literals are frozen.
- **kairos suite on vitest** (internal, test-surface only) — `packages/kairos` migrates its 11 test files (77 cases) from `node:test`/`node:assert` to vitest (`vitest.config.ts` mirrors the engine: `pool: "forks"` · `maxWorkers: 1` · `fileParallelism: false` · `maxConcurrency: 2` · `testTimeout: 20000`); `scripts.test` becomes `vitest run` and the CI `pnpm -C packages/kairos test` command literal is unchanged. The kairos test face converges on the zero-bare-function discipline (12 bare `function` declarations become `const` arrows; `check:no-bare-functions` scope widens to `packages/kairos/tests`). Zero consumer-surface behavior change.
- **Outdated-doc pruning** — the root `CLAUDE.md` P5-stale references are cleaned up, and the maintainers family collapses from five documents + index (48,555B) to three + index (~13KB): `01-template-doctrine.md` / `04-program-experience.md` / `06-skill-node-discipline.md` are folded into a single `01-doctrine.md` (template essence R1-R5 + I1-I4, skill-node principles, the non-mechanical program-experience items), while `02-naming-conventions.md` → `02-naming.md` and `03-context-caching-doctrine.md` → `03-cache-doctrine.md` rename and slim to their durable cores (term registry; six axioms + C1-C7). Consumer links re-point, and the frozen `docs/kairos/{specs,plans}` history is untouched.
