Unified dispatch termination monitor + resume-from-residue (P6 spec T7.5): dispatch death is now one lifecycle — terminate → salvage → resume. `spawnManaged`'s monitor folds two signals (stall: no process-group CPU nor workspace-file mtime growth for the idle window; budget: wall-clock cap) through one pure judge (`terminationCause`) into three distinguishable causes — `stalled` / `over-budget` / `signal` (external SIGTERM) — which the TIMEOUT blocker and carrier archive per cause, so a dead round can be replayed by its death reason. A budgeted or stalled implement round salvages its uncommitted WIP into a standardized `cdd-<op>-<type>-<task>-r<round>-<cause>` git stash (`settleResidue`, `git stash push -u` so brand-new untracked files survive too) and records `recovery.residue_ref` on the failure carrier; the re-dispatch's resume pre-flight reads that carrier, applies the stash back onto the gate-clean tree, and regenerates the brief with a data-driven residue-status appendix so the next agent audits the restored WIP and continues instead of rewriting from zero (a legacy stash-list scan by the standardized message covers pre-schema carriers). Resume-or-discard blocker wording is scoped to the implement lane — the only lane with an auto-resume.

> **Semver note**: the unified monitor + resume capability is an additive feature (2/3-part deletion surface — env timeout keys, `perModeOverride`, execa timeout channel, single `resolveTerminationConfig` resolver — is internal consolidation, no public surface removal beyond the retired env keys) — released as a minor following the P3/P4 precedent.
