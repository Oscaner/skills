## Constraints

- **破坏性变更许可**：`DispatchStep` 异步化是一次 deliberate pin break（P8 §14.3 / D36 同步契约 · 授权来自前提 ①）——不保留旧同步签名，不做双面兼容。
- **零裸函数**：新增物全为类（`Terminator` / `Sampler` / `StallJudge` / `TerminationPolicy`）与其类型；模块级导出仅类型 / 数据 / 类（`check:no-bare-functions` 门）。
- **不造轮子（前提 ⑦）**：进程组建 · 组杀 · SIGTERM→SIGKILL 升级 · 父退出连带杀 · 墙钟上限**全部交 execa**（`^10.1.1` 已装）——引擎不自持任何信号逻辑、不自建第二个墙钟定时器、不复活 T26 的 registry/`reapStale`、不自造后代枚举。
- **绝不用面向用户的 `detached: true`**：它会短路 `cleanup`（`execa/lib/terminate/cleanup.js:6`）；组杀一律走 `killDescendants`。AC 以「`detached` 活面零命中」把门。
- **单源纪律**：预算/时序常量一处（`TerminationPolicy`）；终止因词汇一处（`session/ledger.ts`）；心跳格式一处。零环境变量、零配置 JSON 面。
- **fail-open 是默认姿态**：任一条腿不可读 → 不杀。宁可漏杀（人处置），不可误杀（砍掉正在干活的 child）。
- **execa best-effort 边界如实记录**：`killDescendants` 不覆盖「自成进程组/会话」的后代（`setsid` 起的 daemon 等）；不为此自造枚举。
- **失败面冻结**：终止轮不产生 `next:` 行、不给自动重来、不改 `FAILED_STATUS`（`session/next.ts:160`）。
- **对外契约零变**：CLI 旗标 / 退出码表 0/1/2 / `next:` 字面 / D29 消费面 skill 文本**全部不动** → 无 README / flag help 文案面。
- **历史面不追改**：零残留断言只覆盖活面（引擎 src · 引擎测试 · 模板）。
- **红窗口同任务收口**：T1 的 A 组异步翻面与它**强制的**测试面迁移（`FakeSync` 24 处 · `dispatch:` fixture 全 async · `run.advance()` 91+2 处逐处 await · `sync-runner.test.ts` 四 pin 重落）同属 T1——引擎测试面在 T1 边界即回绿，不留跨任务红窗口；T2–T4 为新增面，不破既有 pin。
- **时序可注入**：判官窗口 / 采样节奏是**参数**（生产取 `TerminationPolicy` 常量，测试注入极小值）——否则端到端僵死 case 要等 30 分钟。
- **语料 pin 已退役（overall D54 · 用户裁定）**：`corpus-form-pin.test.ts` 整体删除——语料完整性属**引擎流程**职责，测试面只校验引擎功能。故本 plan 落仓的语料注册**不再有计数重锚连带**（P11 `6b4e38b1` / spec 侧 `c3521ff1` 那类仪式随之消失）。
- **不发布**：changeset（cdd-engine minor）落 pending；tag / publish = 独立动作。
- **English-primary**（SKILL.md / `docs/*.md`）· specs/plans 中文（Strategy B）· emit 产物派生（`pnpm run emit`）· EOF 恰一 newline。

### Task 2: B 组 stall 判官 + 双信号采样器（fail-open · 时序可注入）
- **Objective**: 在 `face/termination.ts` 内新增 **`StallJudge`**（**纯逻辑 · 零 I/O · 有状态**）：判官不是「两个样本的纯比较」，而是一次派发期间的运行判断——它自持累加态，观测入口 `observe(sample: Sample, now: number): StallVerdict`，逐 tick 喂入样本、返回 `StallVerdict = "progress" | "unknown" | "idled" | "stalled"`（承 T26 语义）。累加态 = `#lastCpuMs`（上一次观测的进程组 CPU）· `#maxMtimeMs`（历史最大 mtime）· `#idleSince`（最近一次"有进展"的时刻，首采置为 spawn 时刻）；构造注入 `idleWindowMs` 与 spawn 时刻（时序可注入是端到端僵死 case 的前提）。`Sample = { groupCpuMs: number | null; newestMtimeMs: number | null }`（`null` = 该腿不可读——字段名与 T3 心跳记录面**同一处命名**，一处命名、两处引用）。判据：**两条腿都必须可读**才判，任一条不可读 → **`unknown` → 永不杀**（fail-open）；CPU 比**上一次观测**（`#lastCpuMs`）增长 **或** mtime 比**历史最大值**（`#maxMtimeMs`）增长 → 重置 `#idleSince` → `progress`；无进展且 `now - #idleSince < idleWindowMs` → `idled`；无进展且 `>=` → **`stalled`**。信号取法：**CPU 腿** = `execFileSync("ps", ["-o", "time=", "-g", String(subprocess.pid)])` 的多行输出求和（`time=` 格式解析为 ms；非零退出 / 解析失败 → `null`）——因约束（`killDescendants` 在 spawn 层强制进程组）child 即组长，**pgid = `subprocess.pid`**（引擎不重算）；**树腿** = 递归遍历 **repoRoot**（child 的 cwd，`face/lifecycle.ts:216-219` 的 `this.#scene.workspace.root.repoRoot`）· 跳过 `.git/` 与符号链接 · 深度上限，取 `statSync().mtimeMs` 最大值 · **显式排除心跳文件的精确路径**（§3.3 消歧硬约束；`.kairos/` **不**整目录排除——child 在 `.kairos/cdd/<slug>/` 下的 handoff 草稿是真进展），目录不可读 → `null`。两条腿的重活（`ps` 求和 / 树遍历 · 皆 I/O）具名落在新类 **`Sampler`**（入口 `probe(): Sample`，构造注入 `{ pgid: number; scanRoot: string; exclude: readonly string[] }`——`pgid = subprocess.pid` · `scanRoot = run.cwd` · 排除项**单源** = `.git/` + `run.heartbeatPath`），由 `Terminator` 每派发持一实例、驱动采样循环（T3）；`StallJudge` 保持**零 I/O**（只吃 `Sample`，不读 OS）。判据：`check:no-bare-functions` 禁模块级 `function`，采样器必须落在类里；且两条腿的重活是 I/O、判官是纯逻辑——分开才各自可测（判官真值表 vs 腿的 fail-open `null`）。判官窗口与采样节奏**是参数**（不读模块级常量），生产由 `TerminationPolicy` 注入、测试注入极小值。明确否决以 child stdout / 输出活动为信号（`claude -p` 可长时间静默思考 → 会误杀好 child）。
