## Program charter

### Goal

把引擎 doc 面两个能力缺口一次收口：**① 消费者整体契约门禁（review-face overall 键）**——engine `face/cli.ts` 的 doc-contract docKey 推导从硬编码 `phaseSpec` 放开为与 validate 同源的推导（`*-overall.md → overall` · 其他 → phaseSpec），consumer 首次可对整体契约跑 `cdd review/fix --type spec --spec <overall>`（零 phase-spec 误报）· kairos cdd-spec-writer 的 overall 变体评审字面可满足（无需 skill 例外）；**② 写文档方案重设计（schema gen 模板写作）**——引擎备几套文档模板：`schema gen <phase-spec|overall|plan>` 从声明面派生**骨架**（标题树 · 表列头 · `- **Version**: v1.0 · <date>` + change-history 首行脚手架——结构 by construction 保真），编排器（cdd-spec-writer/cdd-plan author 节点）**先 gen 后填**——`###`/`##` 类转写失误整类死亡，doc-contract 判定语义不变仍为兜底终判；**③ CLI 框架化收口（2026-10-11 用户裁定 · 原「changesets 收尾」改撤）**——commander ^15 重准入（CLI parse + help 渲染管线 · **CLI 面声明单源 face/declare.ts（v0.7）** 数据驱动 · 行为面全保），变更集收尾（P1/P2 deferred + 框架化 bump）随本 phase 折叠归并，不发布。

### Non-goals
- **不发布**：整理到可发布态即止——`changeset version` / 打 tag / 发布 = 独立动作，不在本程序
- **不改文档方法论语义**：schema gen 骨架 = declare.ts 登记表投影，不引入新文档结构；文档类型语义（overall / plan / phase-spec）、契约、gate 判压全部不变
- **不新增大文档结构 / 新 doc 类型**：模板覆盖既有三型（phase-spec / overall / plan），不发明第四型
- **引擎行为变化 = 能力面 + 六前提重构（2026-10-11 Q2→b 改写 · P1 同持 Q3→c 增注 · P3 同持 cdd-design [P3] Q4 裁定）**：行为语义增量 = review face docKey 推导（P1）+ schema gen 能力（P2）+ help/`--help` 展示面（P1）；**P1/P2/P3 同持整 CLI/face 面重构许可**（face/cli.ts + 组合根 + capsule + words + graph-view + host · 目录级重组 · OOP 统一零裸函数 · 死码/空壳清理 · 高内聚低耦合 · 消费者心智负担 · 最大精简）· P3 重构保**语义契约**（退出码表 0/1/2 · CDD_BLOCKED 通道 · 裸 cdd usage 语义 · 领域 run 语义 · 引擎 vitest 全绿作证）· 零运行时依赖变化（P1/P2 面 · **P3 例外：CLI 框架化 commander ^15 重准入 · D11**）· 零意外行为变化（行为语义不动 · **错误消息/帮助形面/usage 字节开放 commander 原生更替 · 2026-10-11 Q5 裁定**）
- **不 retro-改消费者已发面**：历史 SKILL.md / 文档不作回溯改写（消费面变更只发生在 author 节点表述）

### Cross-cutting（程序级横切约束，先立后执行）
- **模板结构保真由构造保证**：骨架 = declare.ts 登记表派生（标题树 · 表列头 · 版本/change-history 脚手架——`###`/`##` 层级无转写席位）；编辑器在槽位填内容不重排结构
- **gate 零例外底线**：doc-contract 判定语义不变——骨架生成不是 gate 豁免通道（骨架 by construction 绿 · 填后 gate 仍终判兜底）
- **消费面先 gen 后填**：cdd-spec-writer / cdd-plan 的 author 节点从「schema get 参考 + 手工转写」更新为「schema gen 骨架 + 填内容」；`schema get` 保留（声明参考面 · 其他工具/测试消费面不动）
- **CLAUDE.md pin 修订先行**：「cdd CLI 零新子命令」例外面扩 `schema gen`——文档改动与实现同 commit 面落地，不可只实现不改文
- **跨程序树协调（2026-10-11 用户裁定拆 pin → D8）**：本程序 P1/P2 引擎改动**先行实现于现行 `src-next/` 树**（不等 rename P2）——rename sweep 随全库 `grep -rn src-next` 改本程序新文件面（Q3→b 语义 · 豁免面为空）
- **P1 face 重塑保行为等价（2026-10-11 立 · P3 面 2026-10-11 Q5/Q6 裁定增补）**：退出码表（0/1/2 · 0 含 `--help`）· CDD_BLOCKED 通道 · doc-contract 判定语义 · `next:` dispatch 字面——全部零变化，引擎 vitest 全绿作证；**P3 面**：commander 原生为基——错误消息/帮助形面/usage 字节开放原生更替（pins 整体重锚 · deliberate）· 语义契约保：退出码 0/1/2（exitOverride 归一）· CDD_BLOCKED 通道 · 裸 cdd usage 语义（退 2 · 字节原生）· did-you-mean 三 ID 用例语义（命令树结构保真 · 零自定义 hint 码）· `--help` 任意位置 · 领域 run 语义；零运行时依赖变化（**P3 例外：commander ^15 重准入 · 维护文档 05 退役（deliberate · D11/D12）** · 自研 help 渲染面反转）

## Boundary rules

- 每 phase 完整 brainstorm → plan → dev 闭环；serial-phase 硬门：注册 phase 的 hard-dependency 前驱 Design spec ≠ Done → BLOCKED
- **跨程序树协调（D8 · 拆 pin 后）**：本程序 P1/P2 引擎改动先行于现行 `src-next/` 树实现（不等 rename P2）——rename sweep 全库 `grep -rn src-next` 改本程序新文件面（Q3→b · 豁免面为空）
- 需求变更在 phase 中发生时，**先回填本 overall**（version bump + change-history 行 + 同步受影响 phase 的 scope/acceptance/dependency），再继续实现
- **模板结构保真**：schema gen 骨架 = declare.ts 派生（标题树/表列/脚手架 by construction），编辑器只填内容不重排——违反 = 保真破坏，视为 defect
- **gate 零例外**：doc-contract 判定语义不变；模板 / 骨架不是 gate 豁免通道

## Maintenance

- 五表随每 phase 回填：Issue inventory（新增 anchor 注册）、Phase inventory（design/plan 列状态 + dep 边）、Dependency graph（节点变化同步）、Change history（版本行逐 phase 追加）、File paths（新 artifact 行登记）
- Charter only——无任务清单；phase 细节归 phase spec；策略转向立即回填本 overall 后再议实现
- 本程序为引擎 doc 工具面；实施期发现相邻缺口（例如 fill 阶段的结构校验、骨架进可写面），同样回填追加
