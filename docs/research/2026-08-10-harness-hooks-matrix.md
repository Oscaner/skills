# AI Coding Harness — Hooks Matrix (verification for P4a/P4b)

Research question: for each AI coding harness, what HOOKS (lifecycle / prompt-interception / automation config) does it support, with what config format and trust ceremony? This is the hooks reference for the os-engineering **P4a hooks-registration design** (per-harness hooks map) and **P4b gate adapters** (the os-engineering PreToolUse gate port).

**Verification basis**: every claim below was re-fetched 2026-08-13 against the current primary source (official docs / first-party repo), not carried over from the prior research. Differences are flagged in [Verified-against](#2-verified-against-prior-research-2026-08-1012).

## 1. Hooks matrix

Legend — Gate: blocking PreToolUse/BeforeTool analog. Expansion: prompt-interception/rewrite/context-injection analog of Claude's `UserPromptExpansion`.

| Harness | Hooks mechanism | Key events (blocking tool gate / prompt expansion) | Config file / format | Trust ceremony | (a) Blocking tool gate feasible? | (b) Prompt-expansion router feasible? |
|---|---|---|---|---|---|---|
| **Claude Code** | Yes — native hooks | ~34 events. **`UserPromptExpansion`** (fires on slash-command expansion; now blocking-capable: exit 2 blocks the expansion; matcher = command/skill name). **`PreToolUse`** blocking (exit 2 or `permissionDecision: deny`; matcher = tool name; `updatedInput` rewrite). `UserPromptSubmit` blocking, `Stop` blocking, `PostToolBatch`, `TaskCreated`, `TeammateIdle`, `Elicitation`, etc. | `.claude/settings.json` (project/user/local), plugin `hooks/hooks.json`, skill/agent frontmatter `hooks:`; `disableAllHooks`, `allowManagedHooksOnly` | No general trust prompt for settings hooks; subagent frontmatter hooks require workspace trust dialog | **Yes — reference implementation.** Exit 2 / deny, `updatedInput` | **Yes — only harness with a native expansion hook** (injected `Skill(...)` context) |
| **Cursor** | Yes — native hooks (Claude-compatible) | `sessionStart/end`, **`preToolUse`** blocking (`permission: allow/deny`, `updated_input` rewrite), `postToolUse`, `subagentStart/Stop`, **`beforeSubmitPrompt`** (fires after user hits send, before backend request; can *prevent submission* — output only `continue` + `user_message`, **cannot rewrite the prompt**), `beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile`, `afterFileEdit`, `preCompact`, `stop`, `afterAgentResponse`, `workspaceOpen`. Tab hooks: `beforeTabFileRead`/`afterTabFileEdit` | `.cursor/hooks.json` at Enterprise → Team → Project → User levels; `version` + `hooks` map; per-script `command`, `type`, `timeout`, `loop_limit`, `failClosed`, `matcher`. Loads Claude Code hooks too | Workspace must be trusted for project hooks to run | **Yes** — blocking `preToolUse` with deny + `updated_input` | **Partial** — `beforeSubmitPrompt` gates (can block) but cannot expand/rewrite; context injection is via `sessionStart`/`postToolUse` `additional_context` |
| **Gemini CLI** | Yes — native hooks | 11 events, all synchronous. **`BeforeTool`** blocking ("Block Tool / Rewrite" — validate args, block dangerous ops; matcher regex on tool name, e.g. `write_file\|replace`). **`BeforeAgent`** (after user submits, before planning — "Block Turn / Context", closest prompt-interception analog). **`BeforeModel`** (before LLM request — "Block Turn / Mock", can modify prompts). `SessionStart/End`, `AfterAgent`, `AfterModel`, `BeforeToolSelection` (filters tools), `AfterTool`, `PreCompress`, `Notification` | `"hooks"` key in `settings.json` (project `.gemini/settings.json` > user > system > extensions). No separate extension `hooks.json` format documented (extensions can define hooks). Event → matcher group → hooks (`type: command` only, `name`, `timeout` 60000ms) | **Project hooks are fingerprinted** — a changed name/command becomes "new, untrusted hook", warned before execution | **Yes** — blocking `BeforeTool` (needs fingerprint trust handling) | **No true expansion** — `BeforeAgent`/`BeforeModel` can block + add context but not a slash-router primitive |
| **Pi** | No CLI hooks manifest — **TS extensions** | `on('input')` — **rewrites/intercepts the user prompt** (`{action: "transform", text}` or `{action: "handled"}` to answer without LLM). `on('tool_call')` — **blocks/mutates** (`{block: true, reason, terminate}`); mutations visible to later handlers and affect execution. `before_agent_start` (inject message / modify system prompt), `tool_execution_start/update/end`, `tool_result`, `turn_start/end`, `agent_start/end`, session/resource events | No hooks.json. `~/.pi/agent/extensions/` + `.pi/extensions/` (auto-discovered `*.ts` / `*/index.ts`); `pi -e <path>` ad-hoc; extra paths in `settings.json` `extensions`/`packages` | Project-local extensions load only after project is trusted | **Yes via extension** — `tool_call` block (not shell-shippable from build.js) | **Yes via extension** — `input` transform (TS-only) |
| **Codex** | Yes — native hooks (+ plugin-bundled) | 11 events. **`PreToolUse`** blocking (`permissionDecision: deny`/`block`, exit 2, `updatedInput` rewrite). **`UserPromptSubmit`** blocking + `additionalContext`. `PermissionRequest` (allow/deny), `PostToolUse` (`decision: block` replaces result), `PreCompact`/`PostCompact`, `SessionStart`, `SubagentStart/Stop`, `Stop`, `SessionEnd` | `.codex/hooks.json` or inline `[hooks]` in `config.toml`. Event → matcher group → handler (`type: command`; `timeout`, `statusMessage`, `additionalContextLimit`, `async`, `commandWindows`; `prompt`/`agent` types parsed but skipped). Plugin: `hooks/hooks.json` in plugin root or `"hooks"` entry in `.codex-plugin/plugin.json` | **Per-hook trust** — non-managed command hooks reviewed against current hash (changed hooks re-reviewed); `/hooks` to manage; `--dangerously-bypass-hook-trust` for one-off; managed hooks (system/MDM/cloud) trusted by policy | **Yes** — blocking `PreToolUse` (needs per-hook trust) | **No expansion** — `UserPromptSubmit` runs on every prompt, can inject `additionalContext` but not a slash router |
| **Grok Build** | Yes — native hooks, **Claude-compatible** | Events: `SessionStart`, `SessionEnd`, `UserPromptSubmit`, **`PreToolUse`** ("the only blocking event"; deny via stdout `{"decision": "deny"}` or exit 2; fail-open on timeout/crash/malformed), `PostToolUse`, `PostToolUseFailure`, `PermissionDenied`, `Stop`, `StopFailure`, `Notification`, `SubagentStart/Stop`, `PreCompact`/`PostCompact`. No `UserPromptExpansion` | `~/.grok/hooks/*.json` + `<project>/.grok/hooks/*.json`; hooks object keyed by event, optional `matcher` regex on tool names, hooks array with `type` `command`/`http` (+`url`), `command`, `timeout` (default 5s). **Also reads `.claude/settings.json` + `.cursor/hooks.json`** (incl. Cursor camelCase names) | `/hooks-trust` or `--trust`; stored in `~/.grok/trusted_folders.toml` | **Yes** — blocking `PreToolUse` (closest to claude; `GROK_PLUGIN_ROOT`; `/hooks-trust` required) | **No expansion** — `UserPromptSubmit` is passive |
| **OpenCode** | No hooks.json — **plugins** (TS modules / npm) | Hooks object in plugin: **`tool.execute.before`** (block by throwing; rewrite `output.args`), `tool.execute.after`, `session.*`, `message.*`, `permission.asked`, `file.edited`, `command.executed`, `experimental.session.compacting` (inject context or **replace the compaction prompt**). No prompt-rewrite event at submit | `.opencode/plugins/`, `~/.config/opencode/plugins/`, npm packages under `plugin` key in `opencode.json`; no hooks.json | — (plugins are code, loaded locally) | **Yes via plugin** — `tool.execute.before` (TS-only, not shell-shippable) | **No** — no prompt-expansion event (only `tui.prompt.append` + experimental compacting) |
| **Qoder** | Yes — native hooks (Claude-mirror) | Events mirror Claude Code: `SessionStart/End`, **`UserPromptSubmit`** blocking (exit 2 rejects prompt), **`PreToolUse`** blocking (`updatedInput`, `permissionDecision: "ask"`), `PostToolUse(Failure)`, `PermissionRequest/Denied`, `Stop(StopFailure)`, `SubagentStart/Stop`, `PreCompact`/`PostCompact`, `Notification`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `FileChanged`, `WorktreeCreate/Remove`, `Elicitation/Result`. **No `UserPromptExpansion`** | `.qoder/settings.json` hooks key (user `~/.qoder/settings.json`, project `${project}/.qoder/settings.json`, gitignored `.qoder/settings.local.json`, merged). Event → matcher group → hooks (`type`: command/http/prompt/agent; `async`) | **No trust ceremony documented** — edit config, takes effect immediately; plugin hooks get `QODER_PLUGIN_ROOT`/`QODER_PLUGIN_DATA` | **Yes** — blocking `PreToolUse` (Claude-identical event names; no trust flow = simplest port) | **No expansion** — `UserPromptSubmit` runs every prompt |
| **GitHub Copilot** | Yes — Claude-format hooks | 8 events: `SessionStart`, **`UserPromptSubmit`** (inject context), **`PreToolUse`** (block via `permissionDecision: deny`/`ask`; "block dangerous operations, modify tool input"), `PostToolUse`, `PreCompact`, `SubagentStart/Stop`, `Stop`. **No `UserPromptExpansion`** | Workspace `.github/hooks/*.json` (Claude format, `hooks` object); also `.claude/settings.json`/`.claude/settings.local.json`, user `~/.copilot/hooks`, agent `.agent.md` frontmatter `hooks` (Preview, requires `chat.useCustomAgentHooks: true`), plugin `hooks.json`/`hooks/hooks.json`; `chat.hookFilesLocations` setting | — | **Partial — matchers IGNORED**: "hooks run on all tool invocations regardless of the matcher" → a PreToolUse gate would fire on every tool call (P4 with caution) | **No expansion** — `UserPromptSubmit` can inject context only |
| **Trae / Trae-CN** | **Yes — NEW** (docs updated 2026-08-04) | 6 events: `SessionStart` (inject context + env vars via `$TRAE_ENV_FILE`), **`UserPromptSubmit`** (exit 2 = `decision: block`; **plain-text stdout is added to the model as additional context** — a submit-time context-injection analog), **`PreToolUse`** (exit 2 = `permissionDecision: deny`; matcher regex on tool name; modify tool params), `PostToolUse` (attach context), **`Stop`** (exit 2 = `decision: block`, stderr becomes new user query; `loop_limit` caps retries), `Notification` (async, non-blocking) | `~/.trae/hooks.json` (global) + `$PROJECT_FOLDER/.trae/hooks.json` (project). Cursor-style format: `"version":1` + `hooks.<EventName>` → `matcher`, `loop_limit`, `hooks[]` (`type: command`, `command`, `timeout`). **Imports Claude Code hooks** from `.claude/settings.json` / `.claude/settings.local.json` (Settings→Hooks→"Import Hook configuration in CLAUDE"); claude + trae hooks execute in combination | **Yes** — creation shows a security warning panel + "Enable" click; execution mode: **Run in Sandbox** vs **Run Automatically Locally** (outside sandbox, higher risk) | **Yes** — blocking `PreToolUse` (Cursor-compatible format) | **Partial** — `UserPromptSubmit` adds context (plain-text stdout) but cannot rewrite the prompt or route slash commands |
| **Rovo Dev** | `/hooks` command exists — **no hook-event docs** | `/hooks — Manage event hook configurations` (System command). No documented events, payloads, or blocking behavior | Unknown (not documented); config `~/.rovodev/config.yml` | Unknown | **No** (no event docs) | **No** |
| **Mistral Vibe** | Yes — native TOML hooks | 3 events: **`pre_tool`** ("fires per tool call, before the user permission prompt"; `decision: "deny"` blocks, first deny short-circuits; **`hook_specific_output.tool_input` is a full replacement of the model's args**, re-validated vs schema, composed left-to-right), `post_tool` (only if tool body ran; `deny` replaces tool output with reason; can append `additional_context`), `post_agent` (after each turn w/o pending tool calls; deny injects retry message, capped 3 retries/turn) | `./.vibe/hooks.toml` (project, trusted folders only) + `~/.vibe/hooks.toml` (user); project wins on same `name`. `[[hooks]]` fields: `name` (dedup), `type`, `command` (JSON on stdin), `match` (fnmatch glob or `re:` regex, case-insensitive), `timeout` (default 60s), `strict` (failures→denials), `description`. Response: `system_message`, `decision` allow/deny (default allow), `reason`, `hook_specific_output` | Trusted-folders only for project hooks; subagents inherit hook config | **Yes** — blocking `pre_tool` with arg rewrite | **No expansion** — tool-level only |
| **Kiro** | Yes — native JSON hooks | 10 triggers: `PostFileSave/Create/Delete`, **`PreToolUse`** (blocking), `PostToolUse`, **`UserPromptSubmit`** (blocking), `SessionStart`, `Stop`, **`PreTaskExec`** (blocking), `PostTaskExec`. Actions: **`command`** (shell, JSON session context on stdin) or **`agent`** (injects a prompt into the conversation to steer the agent) | `.kiro/hooks/*.json` (any `.json`, kebab-case recommended); `"version":"v1"` + `hooks[]` with `name`, `trigger` (PascalCase), `matcher` (regex; tool name / file path), optional `description`, `timeout`, `enabled`, `confirm` (Stop-trigger interactive confirm + `confirmCommand`) | No trust ceremony documented; supported on IDE + CLI (not Web/Mobile) | **Yes** — blocking `PreToolUse` | **Partial** — `UserPromptSubmit` is blocking but has no expansion/additional-context mechanism; `agent` action is prompt injection (steering), not a router |

## 2. Verified-against (prior research 2026-08-10/12)

Confirmation status of the hooks claims in `/Users/oscaner/Projects/oscaner-skills/docs/research/2026-08-10-harness-marketplace-hooks.md`:

**Confirmed unchanged**
- **Claude Code** — ~30-event count confirmed and expanded to ~34 (adds `Setup`, `PostToolBatch`, `TaskCreated/TaskCompleted`, `TeammateIdle`, `MessageDisplay`, `DirectoryAdded`, `Elicitation/Result`). `UserPromptExpansion` + blocking `PreToolUse` confirmed. New detail: `UserPromptExpansion` is itself blocking-capable; no general trust prompt for settings hooks (workspace trust only for subagent frontmatter hooks).
- **Gemini CLI** — 11 events, `BeforeTool` blocking, fingerprinting, no expansion hook — all confirmed.
- **Pi** — "no CLI hooks; TS extensions" confirmed and expanded: `input` event can rewrite the prompt (`action: transform`) and `tool_call` can block (`{block: true}`).
- **Codex** — `PreToolUse` blocking + per-hook trust + `--dangerously-bypass-hook-trust` confirmed; new detail: `UserPromptSubmit` is also blocking and can inject `additionalContext`.
- **Grok Build** — events, `PreToolUse` sole blocking event, `/hooks-trust`, claude/cursor hook-file compat — all confirmed.
- **OpenCode** — "no hooks.json; plugin events" confirmed; `tool.execute.before` can throw/rewrite; new detail: `experimental.session.compacting` can replace the compaction prompt (still no submit-time prompt rewrite).
- **Qoder** — Claude-mirror events, blocking `PreToolUse`/`UserPromptSubmit`, no `UserPromptExpansion`, no trust ceremony — confirmed.
- **GitHub Copilot** — `PreToolUse` + **matchers ignored** caveat confirmed (the docs state verbatim that matcher values are ignored).
- **Rovo Dev** — `/hooks` command exists, no event docs — confirmed.
- **Mistral Vibe** — `pre_tool` (deny/rewrite `tool_input`), `post_tool`, `post_agent`, TOML `[[hooks]]` — confirmed.
- **Kiro** — 10 triggers, blocking `PreToolUse`/`UserPromptSubmit`/`PreTaskExec`, `command`/`agent` actions — confirmed.

**Changed / refined**
- **Trae / Trae-CN — CHANGED (was "no hooks page found").** TraeCode now documents a full hooks system (docs saved 2026-08-04, i.e. just before the prior research date): 6 events, Cursor-style `hooks.json` at `~/.trae/hooks.json` + `<project>/.trae/hooks.json`, a security-warning "Enable" trust step, sandbox vs local execution modes, and an **"Import hooks from Claude Code"** toggle that reads `.claude/settings.json`/`.claude/settings.local.json` and runs claude + trae hooks in combination. This is a P4b target that the prior research had excluded.
- **Cursor `beforeSubmitPrompt` — REFINED.** Prior research called it "= UserPromptExpansion analog". The current doc says it fires after send and can *prevent* submission, but its output only carries `continue` + `user_message` — it **cannot rewrite or expand the prompt**. Cursor's context injection lives on `sessionStart`/`postToolUse` (`additional_context`), not `beforeSubmitPrompt`. It remains a gate (block the submit) but not an expansion primitive.
- **Gemini extension hooks file** — prior research implied an extension `hooks/hooks.json`; the current doc only states extensions "can define hooks" and documents the `settings.json` `"hooks"` key. Treat extension hook manifests as not-yet-documented.

## 3. P4a / P4b implication

Feasibility for the os-engineering P4a hooks-registration design (per-harness hooks map) and P4b gate adapters (os-engineering PreToolUse gate port):

### P4a — hooks registered via package/marketplace (zero native config for the consumer)
| Harness | Channel | What registers |
|---|---|---|
| Claude Code | `.claude-plugin` plugin `hooks/hooks.json` (already shipped) | UserPromptExpansion router + PreToolUse gate |
| Cursor | Plugin-bundled `hooks.json` (already shipped) | `beforeSubmitPrompt` detect + `preToolUse` enforce |
| Grok Build | **Reads the Claude plugin/marketplace as-is** (`.claude/settings.json`, `.cursor/hooks.json`, `.claude-plugin` marketplaces) | The existing claude/cursor hook files are consumable directly — the root claude marketplace is the P4a channel for Grok |
| Trae | "Import hooks from Claude Code" toggle (reads `.claude/settings.json` + `.claude/settings.local.json`) | Claude hooks re-run in Trae; same-name event I/O may differ (doc warns), so the gate adapter must tolerate Trae's stdin/stdout schema |
| Codex | `.codex-plugin` plugin `hooks/hooks.json` or `"hooks"` entry in `plugin.json` | PreToolUse gate + UserPromptSubmit context (per-hook trust review still applies — user must run `/hooks` once) |
| Qoder | Plugin hooks (`QODER_PLUGIN_ROOT`/`QODER_PLUGIN_DATA` env exist) — `.qoder-plugin` `hooks/hooks.json` path is implied but not explicitly documented | PreToolUse gate (no trust ceremony = simplest install) |
| Copilot | VS Code extension `hooks.json` / `hooks/hooks.json`; also agent `.agent.md` frontmatter `hooks` (Preview flag) | PreToolUse gate — but matchers ignored → gate fires on every tool call (defer/caution) |

### P4a — registered via npm package (extension, not hooks.json)
- **None.** The npm-package harnesses expose hooks only as **TS code**: **OpenCode** plugins (npm package under `plugin` key → `tool.execute.before`) and **Pi** extensions (`pi install npm:…` → `on('input')` / `on('tool_call')`). A shell-based gate/router cannot be shipped here; any P4a extension work for these is TS-shipped and out of scope for the shell gate.

### P4b — native config gate adapters (per-harness config + trust; no package channel)
The os-engineering PreToolUse gate port target set, by closeness to claude:

| Priority | Harness | Adapter shape (P4b) | Trust/ops burden |
|---|---|---|---|
| 1 | **Grok Build** | `.grok/hooks/engineering.json` `PreToolUse` (claude tool-name matchers alias to grok tools; `GROK_PLUGIN_ROOT` env) | `/hooks-trust` (or `--trust`) on each machine; fail-open policy (timeout/crash/malformed do not block) |
| 2 | **Qoder** | `.qoder/settings.json` `PreToolUse` — Claude-identical event names | No trust ceremony — lowest friction |
| 3 | **Trae** | `<project>/.trae/hooks.json` `PreToolUse` (Cursor-compatible format) OR the Claude-import toggle | Security-warning "Enable" on creation; sandbox vs auto-local execution mode must be set |
| 4 | **Codex** | `.codex/hooks.json` `PreToolUse` | Per-hook trust review (hash-based; re-review on change) via `/hooks`; `--dangerously-bypass-hook-trust` for automation |
| 5 | **Gemini CLI** | `.gemini/settings.json` `BeforeTool` (matcher regex on tool names) | Project-hook fingerprinting — changed hook re-warns; blocking events need the fingerprinted trust accepted first |
| 6 | **Vibe** | `.vibe/hooks.toml` `[[hooks]] type = "pre_tool"` (shell command, `match` glob/regex, `strict: true`) | Trusted-folders-only for project hooks; deny semantics + `tool_input` rewrite |
| 7 | **Kiro** | `.kiro/hooks/*.json` `PreToolUse` (action `command`) | No documented trust ceremony |
| 8 | **Copilot** | `.github/hooks/*.json` `PreToolUse` — **defer/caution** | Matchers ignored → runs on every tool call; needs an allowlist in the gate script itself |
| — | **Pi / OpenCode** | N/A for shell gate — TS extension/plugin only | — |
| — | **Rovo Dev** | N/A — no documented hook events | — |

**Prompt-expansion router (P4b "trigger router" question):** only **Claude Code** has a true expansion hook (`UserPromptExpansion`). **Cursor** can *block* the submit (`beforeSubmitPrompt`) but not expand; **Trae** and **Codex** `UserPromptSubmit` can inject context (Trae: plain-text stdout = additional context; Codex: `additionalContext` field) but neither routes slash commands. All others have no submit-time expansion primitive — the per-harness self-check/trigger tables (already in the P3 emit) remain the primary enforcement there.
